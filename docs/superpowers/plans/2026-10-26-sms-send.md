# SMS Send Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an authenticated `POST /sms/send` Nitro endpoint that sends an Alibaba Cloud SMS using server-side environment variables.

**Architecture:** Keep the route thin. `server/routes/sms/send.post.ts` validates `x-sms-token`, `msg`, and `telephone`, then calls a focused `server/utils/aliyun-sms.ts` helper. The helper owns the singleton Alibaba Cloud client, template parameter assembly, and provider error normalization.

**Tech Stack:** Nuxt 4/Nitro, TypeScript, `@alicloud/dysmsapi20170525`, Alibaba Cloud OpenAPI V2 SDK, Docker Compose runtime environment.

**Spec:** `docs/superpowers/specs/2026-10-26-sms-send-design.md`

## Global Constraints

- Credentials remain runtime-only: `ALIBABA_CLOUD_ACCESS_KEY_ID`, `ALIBABA_CLOUD_ACCESS_KEY_SECRET`, and `SMS_SEND_TOKEN` are never committed.
- The request body is exactly `msg` plus `telephone`; `msg` supplies the `code` template variable.
- The production endpoint is the fixed Alibaba Cloud SMS endpoint `dysmsapi.aliyuncs.com`.
- Provider errors are logged server-side without returning raw SDK errors to callers.

## Review Focus

- Missing or incorrect `x-sms-token` must return `401` without calling Alibaba Cloud.
- Non-string, empty, oversized, or invalid Chinese mobile input must return `400`.
- Missing credentials or malformed `SMS_TEMPLATE_PARAM` must fail before a provider call and must not leak secrets.
- A non-`OK` Alibaba response or thrown SDK error must return a stable `502` response.
- The success response must not contain AccessKey values, the send token, or the full provider response.

### Task 2: Implement the Alibaba Cloud SMS helper

**Files:**
- Create: `server/utils/aliyun-sms.ts`

**Interfaces:**
- Produces `sendSms(input: { msg: string; telephone: string }): Promise<{ requestId?: string; bizId?: string }>`.

- [ ] Create one OpenAPI client from runtime credentials and reuse it for requests.
- [ ] Build `SendSmsRequest` with `phoneNumbers`, `signName`, `templateCode`, and JSON `templateParam`; merge the configured template JSON and replace `code` with `msg`.
- [ ] Validate required provider configuration and malformed template JSON before calling Alibaba Cloud.
- [ ] Treat a provider response whose body code is not `OK` as an error without returning the raw response.
- [ ] Preserve provider diagnostics in server logs while returning a generic error to the route.

### Task 3: Add the authenticated Nitro route

**Files:**
- Create: `server/routes/sms/send.post.ts`

**Interfaces:**
- Consumes `POST /sms/send`, header `x-sms-token`, and JSON body `{ msg: string; telephone: string }`.
- Produces `200` on successful send, `401` for token failure, `400` for input failure, and `502` for provider/configuration failure.

- [ ] Read and compare `x-sms-token` with `SMS_SEND_TOKEN`; reject missing runtime token configuration instead of exposing an open endpoint.
- [ ] Validate `msg` and `telephone` at the request boundary; accept a Chinese mobile number matching `^1[3-9]\\d{9}$`.
- [ ] Call `sendSms` only after authentication and validation, and return only stable status/request identifiers.
- [ ] Add a no-provider-call manual probe for unauthorized and invalid requests.
